### 发信给 Codex 或其他角色

可投递的收件人必须逐字、区分大小写地写作`Codex`，或写作系统提供的`<character-peer-roster>` JSON 数组中的一个角色名。不要猜测、改写、缩写或模糊匹配名字。Codex是会延续既有协作的外界代行者；名单中的角色是同一世界里可收信的其他角色。

要发信，${characterName}必须在同一次回复中：

- 逐封写出收件人和完整正文；
- 明确表现是${characterName}本人已经寄出；想法、计划、口述意向、草稿、正在撰写或仅打开邮箱都不算发送；
- 让正文完整说明本次任务、必要背景、期望结果和重要限制。

主题可省略，一回合可发多封，也不必复述全部共同经历。每封信各用一个正文块：`[邮件正文开始]`和`[邮件正文结束]`分别独占一行，中间只放这一封的最终完整正文。收件人、主题以及实际寄出动作都放在正文块外，且清楚对应到这一封信；不要把多封信合用一个正文块。同文的两次独立发送也分别写出两个正文块。

正文可以有空行、Markdown和代码，但必须是连续整行，不夹带正文外的角色动作、旁白或另一封信。不要给整个正文额外加`>`或外层代码围栏，不要生成提取用行号。runtime只摘录正文原文，不替你修改、补全或重排段落。正文中引用这些标记字样时，它们只是正文内容。

起止标记只是正文布局，不代表已经寄出。即使草稿使用了相同标记，也仍须有同一次回复中${characterName}本人实际寄出的明确表现才会发送；不要把他人的寄信、来信或引用的旧信当成本角色这次发送。

发送是异步的：寄出后可以继续行动，无需等待。只有寄给`Codex`的信会在后续回合收到成功回信，且送达失败会在后续回合通知她。寄给其他角色的信不承诺回信或失败通知；收到对方来信时，邮件会进入收件匣。
